# Industrial Pi Agent Demo

基于 [Pi Agent Core](https://www.npmjs.com/package/@earendil-works/pi-agent-core) 的单机工业智能体演示。项目用固定**合成数据**模拟设备异常、知识检索、人工巡检、生产排程和安全评测，展示一个工业 Agent 如何在证据、权限和人工确认约束下工作。

## 项目动机

工业现场的智能化难点不只是“让模型回答问题”，而是让模型围绕设备、测点、工单和生产约束完成可追溯的辅助决策：它需要知道自己能读取哪些数据，必须引用真实证据，遇到缺失数据要停下来，并把最终处置交给现场人员。本项目因此选择一个可复现的本地沙盒，重点演示四件事：

1. **连接现场语境**：案例绑定产线、设备、时序测点、告警和 SOP。
2. **受控地使用 Agent**：Pi Agent 通过 Harness 调用白名单工具，受到案例范围、轮次、次数和时限限制。
3. **形成业务闭环**：诊断结果可以进入知识检索、人工巡检、虚拟复测和排程影响分析。
4. **让结果可验证**：每条结论都展示证据 ID、工具轨迹、确定性风险和人工确认状态。

本项目的目标是教学、方案评审和产品原型验证，不是生产控制系统或预测性维护模型。它不连接真实 SCADA/PLC/MES，不控制设备，也不把待核查假设当成故障定论。

## 10 分钟内启动

需要 Node.js 22.19.0 或更新版本及 npm；推荐使用 `.nvmrc` 中的版本。包版本由 `package-lock.json` 固定。

```bash
npm ci
npm run dev
```

打开 http://127.0.0.1:3000，选案例并点击 **一键演示 · 离线回放**。此路径不需要模型密钥或公网。回放读取 `data/replays.json`，每条轨迹都标注“预录”，调用计数为零。
若 3000 端口已被占用，可运行 `PORT=3120 npm run dev` 并打开 http://127.0.0.1:3120。

启动后可以先点击“**一键演示 · 离线回放**”。这是最适合首次复现和理解系统流程的路径：不需要模型密钥，不访问公网，回放读取 `data/replays.json`，并明确标记为“预录”。

## 部署方式

项目当前支持单机部署，适合本地开发、功能复现或内网原型验证。它没有内置 Docker、反向代理、用户认证或云数据库配置；公网部署前必须补充这些基础设施。

### 本地开发

```bash
npm ci
npm run dev
```

默认监听 `127.0.0.1:3000`。如需修改端口，可使用 `PORT=3120 npm run dev`。

### 生产模式

```bash
npm ci
npm run build
NODE_ENV=production npm start
```

生产服务同样默认只监听本机回环地址。数据库默认写入 `data/demo.sqlite`，可通过 `DATA_DIR=/path/to/data` 指定数据目录。部署账号需要对该目录有读写权限；请在服务停止后用 `npm run reset-data` 清空并重建演示历史。

### 部署检查清单

- 使用 Node.js 22.19.0 或更新版本，并执行 `npm ci`。
- 先运行 `npm run verify`，确认 60 项测试、浏览器验收、类型检查和构建全部通过。
- 在线模式需要在部署机器单独创建 `.env`；不要把密钥写进网页、命令行历史或 Git。
- 生产环境应增加鉴权、限流、HTTPS、日志脱敏、密钥管理和备份策略。
- 不要把 `data/demo.sqlite` 当作共享生产数据库；其中的历史只属于当前演示实例。

## 工作区导航

页面顶部按任务分为四个工作区：**诊断与监测**（案例、设备事件、Agent 诊断和历史）、**知识与巡检**（SOP 和人工工单）、**生产排程**（设备扰动和方案比较）、**评测与安全**（在线评测、安全实验、CSV 数据质量与工业效果指标）。每次只展示一个工作区；地址栏的 `#diagnosis`、`#followup`、`#scheduling`、`#assurance` 可直接打开对应区域，并支持浏览器前进和后退。

离开诊断区会暂停回放；切换工作区会保留当前案例、回放进度和已展开的演示结果。在“知识与巡检”可切换案例；从诊断结果生成工单后会进入该工作区并显示新工单。排程的合成订单与五个诊断案例独立。

## 在线诊断

在**项目根目录**创建本机配置文件，切勿把密钥填到网页或提交到 Git：

```bash
cp .env.example .env
```

复制 `.env.example` 为本机 `.env`；模板默认 `MODEL_PROVIDER=openai`、`MODEL_NAME=gpt-4.1-mini`，只需在 `OPENAI_API_KEY=` 后填写自己的密钥。密钥仅保存在本机 `.env`，不要粘贴到网页、聊天或提交到 Git。保存后运行 `npm run smoke:openai`：它通过真实 Pi Agent 调用 OpenAI，让模型发起一次只读工具调用；成功会打印模型名，不打印密钥。然后**重启** `npm run dev`（或 `npm start`），刷新网页；状态应显示“在线模型已配置”，再点击“在线 Pi Agent 诊断”。此状态只检查本地配置，真实联通以 smoke 命令或在线诊断结果为准。

如改用 DeepSeek，在本机 `.env` 中设置 `MODEL_PROVIDER=deepseek`、`MODEL_NAME=deepseek-flash`、`DEEPSEEK_API_KEY=你的密钥`，运行 `npm run smoke:deepseek`，通过后重启服务并运行一次在线诊断。`deepseek-v4-flash` 也可填入 `MODEL_NAME`，程序会将它解析为当前官方模型 ID `deepseek-flash`；按 DeepSeek 官方文档，旧名称的请求目前由 V4.1 Flash 服务。此配置使用 DeepSeek 官方端点 `https://api.deepseek.com`，不接受第三方网关的密钥。

如改用 Anthropic，将 `MODEL_PROVIDER` 和 `MODEL_NAME` 改为其在当前 Pi 模型目录中支持的模型，填写 `ANTHROPIC_API_KEY`。三家供应商的正常诊断都走同一个 Harness。

当前实现适配 Anthropic、OpenAI 和 DeepSeek 官方端点；第三方兼容接口不能仅靠替换密钥接入。没有密钥或模型名无效时，工作台禁用在线按钮，但回放可用。`.env` 已由 `.gitignore` 排除。

在线请求必须显式携带 `case_id`。Pi Agent Core 发起模型与工具循环；应用 Harness 在工具执行前限制案例、设备、白名单、轮次、次数与时限。两项快照工具在进程内读取 SQLite，新增的只读时序工具读取同案例、同设备的合成测点和确定性告警；维修历史由本地 stdio MCP 子进程查询。两项 Skill 都要求时序工具证据。模型最终 JSON 要与确定性风险和本次真实工具证据一致，否则会话安全失败并保留轨迹。无密钥测试使用 fake 模型，仍由 Pi 实际发起工具调用；如需验证真实供应商连通，请在配置密钥后从工作台运行一次在线诊断。

执行轨迹显示实际模型/工具调用计数、停止原因和 Token 用量状态；展开任一工具记录可查看参数范围、耗时、重试、预算计数和证据 ID。离线回放的实际调用计数保持为零，预录工具记录明确标注未现场计时。

## 数据与风险规则

`data/cases.json` 是唯一案例事实来源，每次启动时导入 SQLite，并保留已有诊断历史。基线为 2026-09-15，快照为 2026-09-22。日产量变化、基线与当前不良率、温度和振动偏移都由后端计算。

| 案例 | 演示目的 | 规则风险 |
| --- | --- | --- |
| `IND-001` | 产量下降且温度、振动同时升高 | `HIGH` |
| `IND-002` | 正常对照 | `LOW` |
| `IND-003` | 仅温度越阈 | `MEDIUM` |
| `IND-004` | 产量下降但关键温度读数缺失，展示拒绝分级 | `UNKNOWN` |
| `IND-005` | 仅振动越阈 | `MEDIUM` |

- `HIGH`：产量下降至少 10%，且温度或振动上升至少 20%。
- `MEDIUM`：上述任意单项越阈，但不满足 `HIGH`。
- `LOW`：数据完整、可比较，且未越阈。
- `UNKNOWN`：关键数据缺失、零基线或日期无法比较。

风险是人工排查优先级，不是已确认的故障原因。结果同时展示证据、待核查假设、人工检查建议与限制。

工作台“跨案例对照”直接展示五个案例的确定性指标和风险，可以切换到任意案例。`IND-004` 的缺失温度不会被画成零值；风险为 `UNKNOWN` 时，在线诊断的结果校验要求放弃故障假设并提出人工数据复核。离线回放的结论同样明确标注数据不足。

工作台的“假设推演”可以临时调整合成日产量、温度和振动，观察同一确定性规则下的风险变化。它只在浏览器内计算，不保存、不改变原案例、Agent 诊断或报告；演示时可用它解释风险阈值与规则边界。

## 在线评测中心

`data/evaluation-suite.json` 固定五个案例、同一问题和预期规则风险，并在服务启动时核对案例数据。配置模型 API 后，工作台可选择两个 Skill 之一运行五案例在线评测。每个任务都经过真实 Pi Agent 与本地 MCP 工具循环，单次结果进入诊断历史，评测批次也写入 SQLite，重启后可恢复查看。

评测逐案记录完成状态、确定性风险一致性、必需工具执行、证据覆盖、`UNKNOWN` 弃判、耗时及停止原因；失败案例保留在分母中。显示的“通过”是 **Harness 合规与流程完成率**，不是故障根因准确率：风险等级已由规则计算并提供给模型，不能据此声称模型独立预测正确。离线预录回放不计入在线评测。一次评测顺序调用五次模型，可能消耗额度并需要数分钟；无密钥时按钮保持禁用。

## 安全实验台

“评测与安全”工作区可运行四个固定场景：越权控制请求、跨案例工具参数、伪造证据 ID、维修工具超时。它们使用脚本化假模型，无需模型 API Key，通过真实 Pi Agent 和 Harness 路径展示输入阻断、工具作用域校验、结果证据校验与超时停止。前两项在对应策略处阻断；伪造证据场景先调用实际本地快照工具和本地 MCP 维修工具，再让结果校验拒绝虚构 ID；超时场景用模拟挂起的 MCP 客户端验证工具超时。每次显示预期与实际停止原因、调用次数、已取得的可信证据和轨迹。

这些是确定性安全边界演示，不是对真实供应商模型安全性的测量。安全实验结果不存入诊断历史，也不计入在线评测。

## 人工巡检闭环

在“设备事件与复测台”的最后一个测点，可点击“基于事件诊断”。问题会包含当前案例、设备和事件时间；离线回放展示预录的时序工具证据，在线模式由 Pi Agent 实际调用只读时序工具。诊断结果同时展示告警的原始测点 ID 和对应 SOP 来源。

从通过证据校验的诊断结果选择责任角色并生成工单。工单保存来源诊断、风险、时序证据、事件时间、SOP ID/版本和检查清单。每项检查需由演示操作员选择“正常/异常/待确认”、填写观察记录；服务端记录时间。全部记录后可标为“检查已完成”，此时**异常仍未确认解除**。有关联告警的工单可保存固定合成样本的虚拟复测及测点证据 ID；复测失败或仍有异常/待确认检查项时禁止确认解除。复测通过后，还需分别勾选产量与质量人工复核并填写说明，才记录“人工确认异常解除（演示）”。工单及这些记录写入 SQLite，重启后可恢复。人工输入与合成复测都不代表真实设备状态。

## 设备知识检索与虚拟排程

工作台“设备知识检索”按当前案例查找 `data/knowledge.json` 中的合成 SOP 卡片，展示文档 ID、版本、日期、命中关键词和人工核查步骤。诊断完成后，也可直接用检查建议作为检索词。该功能采用确定性关键词匹配，无模型密钥时可用；无命中时明确提示，不生成未找到的资料。

“生产排程仿真”读取 `data/scheduling.json` 的四个合成订单和三台虚拟设备。交期优先策略选择最早可完工的兼容设备，能耗优先策略选择单项任务耗电最少的兼容设备；两个策略都按交期顺序处理订单。可模拟任一设备停用，比较完工时间、订单延期和能耗，并查看每台设备的时间线。它是简化的规则沙盒，不代表经过现场校准的数字孪生，也不会把结果下发到 MES 或设备。

排程样例另将 `IND-001 / LINE-03 / EQ-003` 映射到 `M-FAST`：该案例持续告警时，页面自动对比设备正常与停用的两种策略，引用原始测点 ID，并给出“总延期优先、能耗次之”的固定规则建议。存在同源且未解除的工单时，演示人员可填写理由，保存人工选择的仿真方案；历史记录与 KPI 快照持久化到 SQLite。其他案例没有这组订单的资产映射，不会伪装成同一产线。工单人工解除后，正常基线只作为恢复排程的虚拟对照。

## 设备事件与虚拟复测

“设备事件与复测台”读取 `data/operations.json`，将五个案例的合成时序测点绑定到具体产线和设备。选择时间轴上的采样点，可观察温度（°C）、振动（mm/s）、冷却流量（L/min）、原始测点证据 ID 和规则状态。单次越阈为“待确认”，同一指标连续两次越阈才触发持续告警；温度读数缺失时显示“数据缺失”，并要求人工补采。告警对应的建议列出责任角色和 SOP 来源，仅供人员核查。

在最后一个采样点，可先“预览虚拟复测”；此操作不会记录到工单。工单检查完成后可再保存复测结果。系统检查后续两个合成读数是否完整、是否都回到阈值范围；`IND-001` 可演示通过，`IND-003` 可演示仍超温而失败。复测不改变原案例、设备状态或排程。通过仅表示这些模拟测点达标，不能推断产量和质量恢复。阈值及复测分支均未经现场校准；此功能不接 SCADA/PLC，也不是预测性维护模型。

## CSV 测点导入与工业效果

“评测与安全”提供 CSV 导入。格式示例为 `data/telemetry-import-example.csv`，列名中的 `_c`、`_mm_s`、`_l_min` 固定单位；还需案例、产线、设备、带时区时间和 `GOOD`/`BAD` 质量标记。单次导入 2–50 条，时间须严格递增且全部属于当前案例设备。BAD 标记使整批结果进入“数据不足”，不会被当作正常读数或告警。记录和独立证据 ID 保存在本机 SQLite，不覆盖内置案例，也不自动触发 Agent、工单或排程。当前 CSV 合同只接受不带引号、以逗号分列的样例格式。

同页“工业效果与约束评测”按固定合成案例展示首次待确认到告警确认的时间、排程硬约束违规数、交期策略相对能耗策略减少的延期与额外能耗，以及人工选择和导入批次。它衡量的是演示规则和仿真约束，在线模型的 Harness 通过率仍单独显示。OPC UA 只读模拟源未接入，待有明确资产映射和测试环境时再评估。

## API 与会话

API 包括 `GET /api/health`、`GET /api/cases`、`GET /api/cases/{case_id}/snapshot`、`GET /api/agent/capabilities`、`POST /api/diagnose`、`POST /api/replay`、`GET /api/sessions`、`GET /api/sessions/{session_id}`、`GET /api/reports/{session_id}`、`GET /api/evaluations`、`POST /api/evaluations`、`GET /api/evaluations/{id}`、`GET /api/safety-lab/scenarios`、`POST /api/safety-lab`、`GET /api/work-orders`、`POST /api/work-orders`、`PATCH /api/work-orders/{id}/status`、`PATCH /api/work-orders/{id}/checklist/{itemId}`、`POST /api/work-orders/{id}/recheck`、`POST /api/work-orders/{id}/resolve`、`GET /api/knowledge?case_id=&query=`、`GET /api/scheduling`、`POST /api/scheduling/simulate`、`GET /api/scheduling/incident-impact?case_id=`、`GET /api/scheduling/decisions?case_id=`、`POST /api/scheduling/decisions`、`GET /api/operations?case_id=` 和 `POST /api/operations/verify`。历史保存在 SQLite，可按案例及在线/回放模式筛选、分页、恢复查看。报告是可打印 HTML；在线与回放模式在页面、轨迹和报告中分别标明。`POST /api/evaluations` 只接受两个已声明 Skill 的 `skill_id`，使用固定题集；`POST /api/safety-lab` 只接受 `scenario_id` 为 `control-request`、`cross-case`、`forged-evidence` 或 `mcp-timeout`。

新增的隔离导入与工业效果接口为 `POST /api/telemetry/import`、`GET /api/telemetry/imports?case_id=`、`GET /api/industrial-evaluation`。

## 复现与解读流程

1. **0:00–0:30 案例**：选 `IND-001`，指出“合成数据”及快照时间，展示产量下降 15%、温度升高 25%、振动升高 35%。
2. **0:30–0:55 规则推演**：在“假设推演”中提高产量、降低温度和振动，展示风险如何从高变低，再恢复原始值；说明推演不会改写报告。
3. **0:55–1:35 Skill/Harness**：点击一键演示，说明自动选中产线诊断 Skill；暂停回放，展示只读工具、预算和证据校验。
4. **1:35–2:15 轨迹**：逐步查看 Local 产线/设备快照、带原始测点 ID 的时序证据与预录 MCP 维修记录。明确此时是离线预录回放；有模型密钥时可另行运行在线诊断查看真实调用。
5. **2:15–2:45 证据与结论**：继续至结果，展开证据 ID，解释 `HIGH` 表示优先人工排查；冷却回路与轴承只是待核查假设。
6. **2:45–3:00 报告与历史**：打开打印报告，返回工作台查看历史会话。强调没有设备控制或自动处置。

如需理解规则边界，可打开“跨案例对照”，切到 `IND-004` 查看 `UNKNOWN` 与缺失趋势，再对照 `IND-003`、`IND-005` 的单指标异常。如需理解安全边界，可打开“安全实验台”运行跨案例或伪造证据场景，查看实际停止原因。这些都是固定合成案例，不代表真实模型准确率。在线诊断需配置真实模型密钥，离线回放始终标记为预录。

如需展示业务闭环，可先在设备事件台点击“基于事件诊断”，再从诊断结果生成工单。逐项记录人工观察并完成检查，保存虚拟复测证据；通过时再分别确认产量和质量，最后记录人工解除。切到 `IND-003` 可说明复测失败时无法解除。

如需展示调研报告中的“知识助手 + 虚拟验证”方向，可检索“温度”并指出 SOP 卡片的来源和版本；再在排程仿真中切换“高速加工单元停用”，比较两种策略的延期和能耗。说明这些数字只来自固定合成订单和确定性规则。

如需强调工业智能体的现场特点，可在“设备事件与复测台”按 08:00 → 08:05 → 08:10 展示正常、待确认、连续越阈告警，再查看测点 ID、责任角色和 SOP；预览虚拟复测，解释两次测点达标才给出通过。切换 `IND-004` 展示缺失值不能被当作正常，切换 `IND-003` 展示人工检查后仍超温时复测失败。
